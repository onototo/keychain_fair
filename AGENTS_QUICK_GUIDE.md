# Магазин игрушек: краткая инструкция для агентов

Обновлено: 2026-10-04.

Покупатель оформляет заказ в Telegram-боте. Отдельного сайта и веб-админки нет. Печати, OctoPrint, OpenSCAD и кассы в проекте нет.

## Поток заказа

1. Каталог по папкам, карточка товара, корзина.
2. Оплата: наложенный платёж, перевод на карту или ссылка на карту/Apple Pay, если задан `ONLINE_PAYMENT_URL`.
3. Город и отделение Европочты из `config/europost-offices.json`.
4. Имя и телефон.
5. Заказ сохраняется. Администратор из `ADMIN_TELEGRAM_USER_IDS` получает карточку в том же боте и может подтвердить оплату, отметить отправку или отменить заказ.

Лимит корзины — суммарное число штук, `cart.max_units` в `config/app.yaml`, сейчас 99. Одинаковые и разные товары считаются вместе.

Заявка Европочты не создаётся. `keychain_fair/shipping.py` возвращает ручную отправку и оставляет поля `shipment_id`, `tracking_number`, сумму наложенного платежа и объявленную ценность.

## Где крутится магазин

Сервер сейчас — другой домашний ПК пользователя, не машина, с которой идёт разработка. На нём остаются включёнными Windows и Docker, магазин запускается через `docker compose up --build -d`. Пока тот ПК спит или выключен, бот не отвечает. Позже тот же compose переносится на VPS, когда поток заказов вырастет. На этой машине сервер магазина не запускать как постоянный.

`.env` с токеном бота, `INTERNAL_API_TOKEN` и `ADMIN_TELEGRAM_USER_IDS` копируется на ПК магазина вручную. Каталог туда переносится как папка `catalog/`: контейнер читает её с диска без пересборки.

Локальные проверки API на машине разработки: `start_server.bat` → `1`. Постоянный бот — пункт `2` или `docker compose up -d` только на ПК магазина.

## Каталог

`catalog/<категория>/category.yaml` и `catalog/<категория>/<товар>/product.yaml` плюс картинки. API перечитывает папки на каждом запросе.

## Осторожно

- Не удаляйте `data/`, `generated/`, `octoprint/` и `.env`, если пользователь явно не просит.
- Текстовые файлы держать в UTF-8 без BOM.
