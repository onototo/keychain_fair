# Магазин игрушек

Заказы принимаются в Telegram. Каталог лежит в папках репозитория, заказы и сессии бота хранит API в SQLite.

## Каталог

Новая категория — новая папка в `catalog/`. Новый товар — папка внутри неё.

```text
catalog/figurki/category.yaml
catalog/figurki/cherep/product.yaml
catalog/figurki/cherep/1.jpg
```

`category.yaml` содержит `title`. `product.yaml` содержит `title`, `price_byn` и `description`. Картинки `jpg`, `png` или `webp` лежат рядом, первой по имени бот показывает обложку. Папка `catalog/example` — образец, её можно удалить.

В корзине не больше `cart.max_units` штук суммарно. Сейчас это 99, число меняется в `config/app.yaml`.

## Где крутится магазин

Сейчас сервер — отдельный домашний компьютер, не машина, на которой правится код. На нём должны быть включены Windows и Docker. Пока этот компьютер работает и запущен контейнер, бот принимает заказы. Когда он выключен или уснул, бот молчит до следующего включения. Арендованный сервер понадобится позже: туда переносится тот же `docker compose`, заказы и каталог менять не нужно.

На компьютере магазина запуск и остановка:

```bat
start_server.bat
stop_server.bat
```

Проверка на этом же компьютере: `http://127.0.0.1:8120/api/health`. В `.env` там лежат `TELEGRAM_BOT_TOKEN`, `INTERNAL_API_TOKEN` и `ADMIN_TELEGRAM_USER_IDS`. Файл `.env` на другой компьютер копируется вручную, в git он не попадает.

Новые товары правятся в `catalog/` здесь, затем папка каталога переносится на компьютер магазина. Docker читает её сразу, пересобирать контейнер не нужно. Веб-админки нет: заказы приходят в Telegram.

Заявку Европочты программа пока не создаёт. В заказе уже есть отделение, телефон и суммы для будущего API.
